# Допущения и разрешение расхождений

1. Командная архитектура имеет приоритет над техническими названиями в приложенном задании. Сохранены UNDERWRITER, COUNTER_OFFER, SIGNING, ISSUED, /underwriter и формат ошибок RFC 7807. Не добавлены параллельные /bank и DISBURSED.
2. BPMN и существующая стейт-машина совмещают подтверждение подписи и симуляцию выдачи в SIGNING → ISSUED. UI прямо обозначает оба действия в одной кнопке. Принятие оффера — отдельная команда. Отдельный шаг SIGNED → DISBURSED потребует согласованного изменения BPMN, справочника статусов и API и здесь не вводится.
3. Сбой внешней проверки ведёт на ручную проверку, как требуют BPMN и principles.md. Он не становится кредитным отказом. Обновление профиля при недоступном ЕГРЮЛ возвращает 503. Это осознанное отличие от требования вернуть 503 при подаче.
4. Вместо BackgroundTasks используется синхронный ограниченный конвейер в одной транзакции с подачей. Искусственных задержек нет. Клиент получает итог и полный таймлайн без ожидания анимации промежуточных этапов. При необработанном техническом исключении откатываются состояние, аудит, решение и проверки; черновик остаётся редактируемым.
5. Сохранён WireMock из C4. Нового сервиса FastAPI для моков нет. HTTP-клиент на стандартной библиотеке, без изменения lock-зависимостей backend.
6. Командный запрет менять закреплённые ИНН соблюдён. Значения из seed — синтетические идентификаторы длиной 10/12 цифр, они не проходят полноценную проверку контрольных цифр ФНС. Контрольные цифры не заявляются проверенными. Пользовательский ввод произвольного ИНН и регистрация компаний отсутствуют. Перед расширением сценария нужна отдельная миграция идентификаторов и checksum-валидация.
7. Возраст и демоданные привязаны к снимку 2026-10-23. Для client_manual дата 2026-01-23. Уже существующие компании seed не перезаписывает; оценка использует дату из снимка ЕГРЮЛ.
8. Контрпредложение автоматически возможно только при score ≥ 70. Ошибочный пример с 64 из командных материалов заменён воспроизводимым сценарием со 100 баллами и лимитом 6 млн ₽. Баллы не являются вероятностью дефолта.
9. Ставка = ключевая ставка ЦБ + спред продукта + риск-надбавка (одна функция `domain/pricing.py` для автооффера, ручного решения и каталога). Ключевая ставка в `policy.yaml`: 14,0% на 2026-09-11 (решение Совета директоров Банка России); значение нужно сверить с cbr.ru на дату проверки и при необходимости переопределить `KEY_RATE_PCT` / `KEY_RATE_DATE`. Спреды и риск-надбавка синтетические. Runtime не обращается к ЦБ. Каталог показывает «от X%» (без надбавки), `dim_credit_product.rate_nval` заполняется той же функцией при seed.
10. Проверка рассмотрения хранится в существующих credit_decision, decision_factor и external_check. В AUTO-комментарии сохраняются правила, ruleCode, лимит, входы, ответы источников и происхождение полей; клиент внутренний комментарий не получает. Отдельной дублирующей CheckRun-таблицы нет.
11. Явные значения клиента, включая ответ на дозапрос, приоритетнее ФНС/БКИ. Нулевое значение отличается от отсутствующего; пустой ответ источника не затирает ответ клиента. Профиль компании изменяется только по отдельной команде обновления.
12. Идемпотентность submit сохраняет прежний глобальный ключ заявки и возвращает её текущее представление. Для missing-info, offer/accept и sign ключ scoped по пользователю и операции, хранятся хеш тела и исходный ответ. Заголовок у этих команд необязателен для обратной совместимости; новый UI его передаёт. Повтор без ключа отклоняется проверкой состояния, повторной выдачи не происходит.
13. Fallback WireMock для остальных цифровых идентификаторов фиксирован и воспроизводим; это одинаковый базовый профиль, без персонализации по ИНН. Реальные интеграции, SMS, документы, ЭЦП и LLM отсутствуют.
