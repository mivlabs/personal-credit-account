# Тестовые аккаунты

Все данные синтетические. Пароль у всех аккаунтов: **`demo1234`**. Вход: `POST /api/v1/auth/login`.

Аккаунты и компании создаёт seed при старте контейнера `api` (после миграций). Он идемпотентен: повторный запуск
ничего не дублирует и не перезаписывает существующих пользователей и компании.

> **ИНН закреплены.** Под них сделаны стабы WireMock (ЕГРЮЛ / ФНС / БКИ), менять их нельзя.

Цифры условные: итоговые значения зависят от скоринг-карты и порогов (политика: балл ≥ 70 — авто, 40–69 — ручная
проверка, < 40 — отказ).

|---|---|---|---|

| `client_timeout` | Овердрафт, 500 тыс. ₽ | БКИ возвращает синтетический 503 | `EXTERNAL_CHECK → SCORING → MANUAL_REVIEW`, причина недоступности БКИ |

Настоящий таймаут источника: ИНН `7701000099` (отдельного логина нет, используется в тесте `test_slow_source_is_timeout_within_budget`): БКИ отвечает с задержкой 2 с, опрос укладывается в бюджет `EXTERNAL_CHECKS_BUDGET_SECONDS` (по умолчанию 3 с), источник получает статус `TIMEOUT`.

## Проверка на своём ИНН

Любой валидный ИНН можно зарегистрировать самому: `POST /api/v1/auth/register` (на экране входа — вкладка «Зарегистрироваться по ИНН»). ИНН проверяется по контрольным числам ФНС (10 цифр у организации, 12 у ИП); данные компании подтягиваются из ЕГРЮЛ-мока.

**Сценарий проверки задаёт 9-я цифра 10-значного ИНН** (у 12-значного ИНН ИП — 10-я цифра, перед двумя контрольными). Последняя цифра контрольная и свободно не выбирается, поэтому сценарий привязан к предыдущей. Моки ЕГРЮЛ/ФНС/БКИ детерминированы по этой цифре и отвечают на любой валидный ИНН; закреплённые ИНН seed-аккаунтов имеют приоритет.

Заявка во всех строках: «Оборотный кредит», срок 12 месяцев.

Название компании в моке содержит ИНН («ООО «Синтетика 7702000050»», «ИП Синтетика 770200000523»). Для цифры 5 возраст считается от настоящей даты, поэтому при `AS_OF_DATE` по умолчанию (сегодня) исход не меняется со временем; в тестах `AS_OF_DATE` зафиксирован, и для этого сценария его подменяют на сегодняшнюю дату.

Пример регистрации:

```bash
curl -s -X POST http://localhost:8000/api/v1/auth/register   -H 'Content-Type: application/json'   -d '{"login":"my_company","password":"secret123","inn":"7702000011"}'
```

Ответ такой же, как у входа (`accessToken`, `user`). ИНН и логин уникальны: повторная регистрация даёт 409 (`INN_TAKEN` / `LOGIN_TAKEN`).
