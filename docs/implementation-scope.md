# Объём реализации и инвентаризация

Срез исходного репозитория: API с ролями CLIENT/UNDERWRITER, PostgreSQL и 12 таблиц, Alembic, черновики, аудит, ручные решения, офферы и симуляция подписания. WireMock был пуст, интеграции отключены, скоринг возвращал MANUAL_REVIEW, frontend отсутствовал.

Приоритет источников: командный план PDF, User story.docx (US-01…US-15), principles.md, konspekt-sozvona.md, C4, BPMN, data-dictionary.md, существующий контракт API. Отдельного оригинала официального кейса в репозитории нет. Расхождения приложенного технического задания разрешены в assumptions.md.

| Функциональность | Реализация |
|---|---|
| US-01, US-10: выбор продукта и рекомендации по цели | Три продукта; `POST /products/recommendations` ранжирует их по цели, сумме и сроку по правилам `recommendation.yaml` (7 категорий целей), возвращает `matchScore`, `recommended`, `reasons`, `rateFrom`; без LLM |
| US-02: профиль по ИНН | Профиль компании и обновление из локального ЕГРЮЛ |
| US-03: черновик | Общий мастер, автосохранение полей и шага в PostgreSQL |
| US-04: подача | Проверка диапазонов, блокировка строки, идемпотентная подача |
| US-05: прозрачный статус | Этапы из API, история, следующий шаг |
| US-06: дозапрос | Только запрошенные поля, новый набор HTTP-проверок и новое решение |
| US-07, US-08: оффер и выдача | Сравнение условий, принятие/отказ, явная симуляция подписи и выдачи |
| US-09: причины решения | Причина клиенту, банку баллы и объяснения факторов |
| US-11…US-14: банк | Очередь с фильтрами и пагинацией, карточка, проверки, решение с комментарием, аудит |
| Пять исходов | Рассчитываются общей политикой из YAML и признаков компании |
| Защита повторов | Сохранённые ответы команд и UNIQUE на выдачу |
| US-15: дашборд | Следующая итерация после MVP; в эту реализацию не включён |

Последовательность выполненной работы: конвейер и правила → WireMock и HTTP-клиент → UI клиента и банка → защита команд → тесты и документация. Текущее решение сохраняет модульный монолит, C4-контейнеры и статусы BPMN.
